  <action>
Create FileStorageService to abstract file path handling for floor plan images, implementing FOUND-04 requirement (relative paths, not absolute):

**FileStorageService interface:**
- toRelativePath(absolutePath: string, databasePath: string): string
  - Converts absolute file path to path relative to database file location
  - Example: If database is C:\Projects\myproject.assetmap and image is C:\Projects\images\floor1.png
  - Returns: "images/floor1.png" (relative to database directory)
  - Use Node.js path.relative() for cross-platform compatibility

- toAbsolutePath(relativePath: string, databasePath: string): string
  - Resolves relative path back to absolute path for image loading
  - Example: If database is C:\Projects\myproject.assetmap and relative path is "images/floor1.png"
  - Returns: "C:\Projects\images\floor1.png"
  - Use path.resolve() to combine database directory with relative path

- normalizePath(filePath: string): string
  - Normalizes path separators (backslash → forward slash) for database storage
  - Ensures consistent path format across Windows/Mac/Linux

**Implementation notes:**
- Use Tauri path API (@tauri-apps/api/path) to get database directory: path.dirname(databasePath)
- Store paths in database using forward slashes (/) for cross-platform compatibility
- Handle edge cases: absolute paths that are NOT under database directory (warn but allow - user might have images elsewhere)
- Critical blocker from STATE.md: "Must use database-relative paths for images — enables storage migration"

**Why this matters:**
- Absolute paths break when database moved to different folder or different computer
- Relative paths allow database + images folder to be moved together
- Enables backup/restore workflows and cloud storage (if user ignores cloud folder warning)

Export FileStorageService from src/infrastructure/services/index.ts.
