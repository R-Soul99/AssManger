  <action>
Add two new tables and migrate existing categories table:

**assetTypes table:**
- id: text (primary key)
- name: text (NOT NULL, unique)
- description: text (nullable)
- icon: text (NOT NULL, default 'FaBox')
- color: text (NOT NULL, default '#000000')
- is_system_type: integer boolean (NOT NULL, default 0)
- created_at: integer timestamp (NOT NULL)
- updated_at: integer timestamp (NOT NULL)

**customFieldDefinitions table:**
- id: text (primary key)
- asset_type_id: text (NOT NULL, references assetTypes.id, onDelete: cascade)
- field_name: text (NOT NULL)
- field_type: text enum ['text', 'number', 'date', 'dropdown', 'checkbox', 'link'] (NOT NULL)
- required: integer boolean (NOT NULL, default 0)
- dropdown_options: text (nullable, stores JSON array for dropdown type)
- default_value: text (nullable, stores JSON-encoded value)
- display_order: integer (NOT NULL, default 0)
- created_at: integer timestamp (NOT NULL)
- updated_at: integer timestamp (NOT NULL)
- UNIQUE constraint on (asset_type_id, field_name) to prevent duplicate field names per type

**Migration strategy:**
1. Create assetTypes and customFieldDefinitions tables
2. Migrate data from categories table to assetTypes (preserve id, name, description, icon, color)
3. Update assets.category_id column to assets.asset_type_id (rename column, maintain foreign key)
4. Seed system asset types: PC, Phone, Printer, Monitor, Electronics, Machinery (if not already present from migration)
5. Drop categories table (no longer needed)

Update schema relations to link assetTypes → customFieldDefinitions and assets → assetTypes.

Custom fields implementation: Use JSON text column per Claude's discretion (CONTEXT.md allows this approach). This avoids complex EAV tables while supporting unlimited custom fields. Note: User decided on FEATURES (unlimited fields, rich types), Claude's discretion allows JSON column for storage mechanism.

Run `npm run db:generate` to create migration.
