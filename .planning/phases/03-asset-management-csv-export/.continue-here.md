The app currently shows the welcome screen and allows project creation (mock), but clicking

call RepositoryFactory.getInstance() synchronously during render.

<decisions_made>
- Vite alias approach chosen over dynamic imports for the better-sqlite3 fix: simpler, no API changes,
  aliases apply globally to all files that import better-sqlite3 regardless of depth
- Alias order in vite.config.ts: drizzle-orm/better-sqlite3/migrator first, then drizzle-orm/better-sqlite3,
  then better-sqlite3 — prevents prefix matching from swallowing the migrator path
- In-memory mocks chosen over sql.js or @tauri-apps/plugin-sql: zero new dependencies, sufficient for UAT,
  the real DB layer will be implemented via Tauri IPC in a future phase
- RepositoryFactory fallback strategy preferred over replacing the class entirely: preserves the singleton
  pattern and all existing component code unchanged
</decisions_made>

<context>
The project architecture has a mismatch that was never caught by automated verification:
ProjectService uses connection.mock.ts (no-op stubs) but RepositoryFactory and all
components use the real connection.ts which requires better-sqlite3. This was invisible
in grep-based verification but surfaces immediately when running the app.

The mock repository approach is the minimal-change fix. Each mock just needs an array store
and simple filter logic. The AssetRepository mock is the most involved because
findAllWithRelations needs to join with categories and locations and build location paths.

Key interfaces (already read, shapes understood):
- ICategoryRepository: create, findAll, findById, update, delete (Category has numeric id)
- ILocationRepository: findById, findAll, findByType, findChildren, findRoots, save, update,
  delete, hasChildren, hasAssets (Location has string uuid id, type enum, parentId nullable)
- IAssetRepository: findById, findAll, findAllWithRelations, findByLocation, findByTag,
  tagExists, save, update, delete, count (Asset has string uuid id)

Entity construction:
- Category is a plain interface (just assign properties)
- Location and Asset are classes with static create(input) factory returning CreateResult<T>
  But repositories return the entity instances — Location.create() and Asset.create() do
  Zod validation via safeParse. The mock repos should use these factories.

AssetWithRelations shape (returned by findAllWithRelations):
  { asset: Asset, category: CategoryData | null, location: LocationData | null, locationPath?: string }
</context>
