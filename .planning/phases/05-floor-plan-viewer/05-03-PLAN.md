# Phase 05 Plan 03: Marker Rendering with Category Styling

## Objective

Implement the service, hook, and canvas rendering pipeline for displaying asset markers on floor plans. Markers should appear at their normalized coordinate positions, scale with zoom, and display category-specific colors and icon initials. Include click detection to identify selected markers.

## Tasks

<task id="1" name="Create MarkerService">
Create `src/application/services/MarkerService.ts`:
- `getMarkersWithDetails(floorPlanId)`: fetch all markers for floor plan
- Join with asset and category data in parallel (Promise.all for performance)
- Export `MarkerWithDetails` type: Marker + asset name/tag/status/serialNumber + category name/color/icon
- Handle missing assets (skip with warning) and missing categories (use default gray)
- Use lazy repository initialization (lazy getters, not constructor) to avoid startup errors
- Export singleton `markerService` instance
</task>

<task id="2" name="Create useMarkers hook">
Create `src/presentation/hooks/useMarkers.ts`:
- Accept `floorPlanId: string | null`
- Return `{ markers: MarkerWithDetails[], loading: boolean, error: string | null }`
- Reactive to floorPlanId changes (useEffect dependency)
- Return empty array when no floorPlanId provided
</task>

<task id="3" name="Render markers on canvas">
Update `FloorPlanCanvas.tsx`:
- Accept `markers: MarkerWithDetails[]` prop
- Implement `drawMarker(ctx, marker, canvasWidth, canvasHeight)` function:
  - Convert normalized coords (0-1) to pixel coords: `x = marker.x * canvasWidth`
  - Draw filled circle with category color
  - Draw category initial letter in white, centered
  - Draw selection ring (black border) if marker is selected
- Render markers in canvas `draw` effect after image
- Implement click detection: hit-test click position against marker positions
- Expose `selectedMarkerId` state
</task>

## Verification

- Markers visible on canvas at correct positions
- Category colors applied correctly
- Click selects marker (selection ring appears)
- No TypeScript errors
