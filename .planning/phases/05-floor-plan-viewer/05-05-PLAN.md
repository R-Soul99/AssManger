# Phase 05 Plan 05: Filtering and Visibility Controls

## Objective

Add filtering and visibility controls per CONTEXT.md decisions: category toggle chips in the toolbar (always visible) and a collapsible sidebar for status filtering. Non-matching markers dim to 30% opacity rather than hiding. Wire FloorPlanCard with View/Edit buttons and integrate FloorPlanViewer into the navigation flow.

## Tasks

<task id="1" name="Create FloorPlanViewerToolbar">
Create `src/presentation/components/floorplan/FloorPlanViewerToolbar.tsx`:
- Accept `categories: CategoryData[]`, `visibleCategories: Set<string>`, `onToggleCategory`, `onShowAll`, `onHideAll`, `onToggleSidebar` props
- Display category chips: colored (category.color), show initial letter
- Active chip = full color; inactive = greyed out
- "All" and "None" buttons for bulk toggle
- Sidebar toggle button (FilterList icon)
- Position absolute at top-left of viewer
</task>

<task id="2" name="Create FloorPlanFilterSidebar">
Create `src/presentation/components/floorplan/FloorPlanFilterSidebar.tsx`:
- Accept `open: boolean`, `selectedStatus: string | null`, `onSelectStatus`, `markerCounts: Record<string, number>` props
- Collapsible MUI Drawer on right side
- Status options: Active, Inactive, Faulty, Decommissioned, plus "All" (null)
- Color-coded left border per status
- Marker count badge per status
- Selected status shown with checkmark
- Use `ListItemButton` (MUI v7 compatible — not `ListItem button` prop)
</task>

<task id="3" name="Integrate filtering into canvas rendering">
Update `FloorPlanCanvas.tsx`:
- Accept `visibleCategories: Set<string>`, `selectedStatus: string | null` props
- In `drawMarker`: check category visibility and status filter
- Non-matching markers: `ctx.globalAlpha = 0.3` (30% opacity)
- Matching markers: `ctx.globalAlpha = 1.0`
- Dimmed markers remain clickable (selection still works)

Update `FloorPlanViewer.tsx`:
- Manage `visibleCategories` state (Set<string>, initialized from markers)
- Manage `selectedStatus` state (string | null)
- Calculate `markerCounts` per status from markers array
- Pass filter state to FloorPlanViewerToolbar, FloorPlanFilterSidebar, FloorPlanCanvas
- Manage sidebar open/close state
</task>

<task id="4" name="Wire FloorPlanViewer into navigation">
Update `FloorPlanCard.tsx`:
- Add View and Edit buttons in CardActions
- View button: `onView(floorPlan.id)` callback
- Edit button: opens FloorPlanDetailView (existing behavior)
- Buttons hidden in selection mode

Update `FloorPlanList.tsx`:
- Add `viewingPlanId: string | null` state
- Show FloorPlanViewer when `viewingPlanId` is set
- Pass `onBack` callback to viewer (back button in top-left)

Update `FloorPlanViewer.tsx`:
- Accept optional `onBack?: () => void` prop
- Back button (styled like zoom controls) in top-left, only when `onBack` provided
</task>

## Verification

- Category chips toggle marker visibility
- Status filter dims non-matching markers
- Select All/None work
- Sidebar opens/closes
- View button on card opens viewer
- Back button returns to list
- No TypeScript errors
